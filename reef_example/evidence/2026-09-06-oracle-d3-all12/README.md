# 12 道题在 depth<=3 下的穷举上界(2026-09-06)

```bash
uv run python tasks/oracle_chains.py --depth 3 --out work/oracle.json
```

确定性:工具是确定性的,底图由固定 seed 生成,所以同样的命令得到同样的数。

## 为什么留着它

`data.max_score` 是一个**绝对**阈值(0.5),而这 12 道题的上界差 **46.5 倍**:

```
最低  haze_00          0.0215
最高  low_light_00 / noise_01   1.0000
```

拿一把尺子量 46 倍的量程,结果是 12 题里 4 题判反(贪心基线的分,见 greedy_scores.json):

| 任务 | 上界 | 拿到 | 达成率 | 绝对阈说 | 后果 |
|---|---|---|---|---|---|
| low_light_00 | 1.0000 | 0.6564 | 66% | 成功 | **永不进 batch**,propose 从没见过这道有巨大改进空间的题 |
| low_light_01 | 0.9650 | 0.6695 | 69% | 成功 | 同上 |
| haze_noise_00 | 0.2019 | 0.2281 | 113% | 失败 | 进 batch,让 propose 为一道已做到头的题找不存在的改进 |
| haze_noise_01 | 0.4071 | 0.4766 | 117% | 失败 | 同上 |

也就是说 batch 的组成本身是偏的 —— 该学的进不来,已到极限的混进来。挪阈值救不了。
`materialize.py` 于是把上界随任务下发,`run.py` 报**达成率**而不是绝对分。

## 一个必须说清楚的局限

这是 **depth<=3 预算下**的上界,而中继允许更多步(`RECORD_MAX_TURNS=6`)。所以达成率
可以超过 100% —— 那是"多走几步越过了少步上界",不是算错。要把它当严格上界用,得跑
同预算的 oracle(depth 6 是 6^6 条链,慢得多)。

这条局限值得写下来,是因为这个仓栽过同一个坑:2026-09-03 曾用 ≤5 步的上界去判一个
步数不受限的 episode,得出"泄题分越过物理上界"的结论,后来撤回了。**比较之前先说出
是什么让两个数可比。**
